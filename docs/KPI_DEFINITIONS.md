# TransitOps KPI Definitions

This document details the exact mathematical formulas, SQL queries, boundary conditions, and role matrices for all Key Performance Indicators (KPIs) calculated by the TransitOps system.

---

## 1. Metric Specifications

### 1.1 Active Fleet
- **Definition**: Number of active vehicles currently deployed on a trip.
- **Unit**: Count (Integer)
- **Mathematical Formula**:
  $$\text{Active Fleet} = \sum [v.\text{status} = \text{'On Trip'} \land v.\text{is\_active} = \text{true}]$$
- **SQL Implementation**:
  ```sql
  SELECT COUNT(*) FROM vehicles 
  WHERE status = 'On Trip' AND is_active = true;
  ```

### 1.2 Utilization Percentage
- **Definition**: Proportion of non-retired, active fleet vehicles currently deployed on a trip.
- **Unit**: Percentage ($0.00\% - 100.00\%$)
- **Mathematical Formula**:
  $$\text{Utilization \%} = \frac{\text{Active Fleet}}{\text{Non-Retired Active Vehicles}} \times 100$$
  *Edge Case*: If $\text{Non-Retired Active Vehicles} = 0$, Utilization is $0.00\%$.
- **SQL Implementation**:
  ```sql
  SELECT COALESCE(
    ROUND(
      (COUNT(*) FILTER (WHERE status = 'On Trip' AND is_active = true) * 100.0) / 
      NULLIF(COUNT(*) FILTER (WHERE status != 'Retired' AND is_active = true), 0),
      2
    ),
    0.0
  ) FROM vehicles;
  ```

### 1.3 Total Revenue
- **Definition**: Gross revenue earned strictly from **Completed** trips within the selected date range. Cancelled, Dispatched, or Draft trips contribute \$0.00.
- **Unit**: Currency (USD, 2 decimal places)
- **Mathematical Formula**:
  $$\text{Revenue} = \sum_{t \in \text{Completed Trips in Range}} t.\text{revenue}$$
- **SQL Implementation**:
  ```sql
  SELECT COALESCE(SUM(revenue), 0)
  FROM trips
  WHERE status = 'Completed'
    AND ($from::DATE IS NULL OR (COALESCE(completed_at, updated_at) AT TIME ZONE 'UTC')::DATE >= $from::DATE)
    AND ($to::DATE IS NULL OR (COALESCE(completed_at, updated_at) AT TIME ZONE 'UTC')::DATE <= $to::DATE);
  ```

### 1.4 Total Distance
- **Definition**: Total distance traveled by completed trips. Calculated as `final_odometer - start_odometer` when final odometer is greater than or equal to start odometer; falls back to `planned_distance` if odometer difference is missing or null.
- **Unit**: Kilometers (km, 1-2 decimal places)
- **Mathematical Formula**:
  $$\text{Distance} = \sum_{t \in \text{Completed Trips in Range}} \begin{cases} t.\text{final\_odometer} - t.\text{start\_odometer} & \text{if } t.\text{final\_odometer} \ge t.\text{start\_odometer} \\ t.\text{planned\_distance} & \text{otherwise} \end{cases}$$
- **SQL Implementation**:
  ```sql
  SELECT COALESCE(SUM(
    CASE 
      WHEN final_odometer IS NOT NULL AND start_odometer IS NOT NULL AND final_odometer >= start_odometer 
        THEN (final_odometer - start_odometer)
      ELSE planned_distance
    END
  ), 0)
  FROM trips
  WHERE status = 'Completed'
    AND ($from::DATE IS NULL OR (COALESCE(completed_at, updated_at) AT TIME ZONE 'UTC')::DATE >= $from::DATE)
    AND ($to::DATE IS NULL OR (COALESCE(completed_at, updated_at) AT TIME ZONE 'UTC')::DATE <= $to::DATE);
  ```

### 1.5 Total Operational Cost
- **Definition**: Combined sum of all logged trip/fleet expenses (Fuel, Toll, Maintenance, Other) in date range plus all closed workshop maintenance log costs in date range.
- **Unit**: Currency (USD, 2 decimal places)
- **Mathematical Formula**:
  $$\text{Operational Cost} = \sum_{e \in \text{Expenses in Range}} e.\text{cost} + \sum_{m \in \text{Closed Maintenance Logs in Range}} m.\text{cost}$$
- **SQL Implementation**:
  ```sql
  SELECT 
    (
      SELECT COALESCE(SUM(cost), 0) FROM expenses 
      WHERE ($from::DATE IS NULL OR date >= $from::DATE)
        AND ($to::DATE IS NULL OR date <= $to::DATE)
    ) + (
      SELECT COALESCE(SUM(cost), 0) FROM maintenance_logs
      WHERE status = 'Closed'
        AND ($from::DATE IS NULL OR end_date >= $from::DATE)
        AND ($to::DATE IS NULL OR end_date <= $to::DATE)
    ) AS total_operational_cost;
  ```

### 1.6 Fuel Efficiency
- **Definition**: Average fleet distance traveled per liter of fuel consumed.
- **Unit**: km / L (2 decimal places)
- **Mathematical Formula**:
  $$\text{Fuel Efficiency} = \frac{\text{Total Distance}}{\text{Total Fuel Liters}}$$
  *Edge Case*: If $\text{Total Fuel Liters} = 0$, Fuel Efficiency is `null`.
- **SQL Implementation**:
  ```sql
  SELECT CASE 
    WHEN total_fuel_liters > 0 THEN ROUND((total_distance / total_fuel_liters)::numeric, 2)
    ELSE NULL
  END;
  ```

### 1.7 Return on Investment (ROI) per Vehicle
- **Definition**: Percentage return generated by each vehicle over its acquisition cost.
- **Unit**: Percentage (can be negative if operational costs exceed revenue)
- **Mathematical Formula**:
  $$\text{ROI}_v = \frac{\text{Completed Trip Revenue}_v - \text{Operational Cost}_v}{\text{Acquisition Cost}_v} \times 100$$
  *Edge Case*: If $\text{Acquisition Cost}_v = 0$, ROI is `null`.

### 1.8 Pending Trips
- **Definition**: Trips awaiting execution or currently en route.
- **Unit**: Count (Integer)
- **Mathematical Formula**:
  $$\text{Pending Trips} = \sum [t.\text{status} \in \{\text{'Draft'}, \text{'Dispatched'}\}]$$
- **SQL Implementation**:
  ```sql
  SELECT COUNT(*) FROM trips WHERE status IN ('Draft', 'Dispatched');
  ```

## 2. Role-Based Access Matrix

| Endpoint | Allowed Roles | Forbidden Roles | Behavior |
| :--- | :--- | :--- | :--- |
| `GET /api/v1/dashboard/kpis` | Admin, Fleet Manager, Financial Analyst, Safety Officer | Driver | 403 Forbidden for Driver; returns fleet aggregates without Driver PII. |
| `GET /api/v1/dashboard/me` | Driver | Admin, Fleet Manager, Financial Analyst, Safety Officer | 403 Forbidden for non-Drivers; returns only driver's own trips and distance, zero financial metrics. |
| `GET /api/v1/dashboard/export.csv` | Admin, Fleet Manager, Financial Analyst | Driver, Safety Officer | 403 Forbidden for Driver & Safety Officer; streams CSV with sanitized formula injection prefix. |
