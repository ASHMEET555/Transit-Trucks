# Phase 2 Inventory & Technical Audit Notes

## 1. Current Schema Inventory (from Phase 1 Migrations)

### Tables
1. **`users`**
   - Columns: `id` (UUID string), `email` (TEXT PK), `password_hash` (TEXT), `role` (TEXT), `is_active` (BOOL), `driver_license` (TEXT, nullable), `created_at` (TIMESTAMPTZ), `updated_at` (TIMESTAMPTZ).
   - Constraints: Primary Key on `email`. No check on role enum.
   - Indexes: Primary key index on `email`.

2. **`sessions`**
   - Columns: `token_hash` (VARCHAR(64) PK), `user_email` (TEXT FK to `users.email`), `created_at` (TIMESTAMPTZ), `expires_at` (TIMESTAMPTZ), `absolute_expires_at` (TIMESTAMPTZ), `last_seen_at` (TIMESTAMPTZ), `ip` (VARCHAR(45)), `user_agent` (TEXT).
   - Constraints: Foreign key `user_email` REFERENCES `users(email)` ON DELETE CASCADE.
   - Indexes: `idx_sessions_user_email`, `idx_sessions_expires_at`.

3. **`login_attempts`**
   - Columns: `id` (BIGSERIAL PK), `email` (VARCHAR(255)), `ip` (VARCHAR(45)), `attempted_at` (TIMESTAMPTZ), `success` (BOOLEAN).
   - Indexes: `idx_login_attempts_email_time`, `idx_login_attempts_ip_time`.

4. **`destinations`**
   - Columns: `name` (TEXT PK), `region` (TEXT NOT NULL).
   - Constraints: Primary Key on `name`. No check constraints.

5. **`vehicles`**
   - Columns: `registration_number` (TEXT PK), `model` (TEXT NOT NULL), `type` (TEXT NOT NULL), `max_load_capacity` (DOUBLE PRECISION NOT NULL), `odometer` (DOUBLE PRECISION NOT NULL), `acquisition_cost` (DOUBLE PRECISION NOT NULL), `status` (TEXT NOT NULL DEFAULT 'Available').
   - Gaps: No `is_active` soft-delete column. `DOUBLE PRECISION` used instead of `NUMERIC(10,1)` / `NUMERIC(12,2)`. No CHECK constraints on `status`, `type`, or positive values.

6. **`drivers`**
   - Columns: `license_number` (TEXT PK), `name` (TEXT NOT NULL), `license_category` (TEXT NOT NULL), `license_expiry_date` (TEXT NOT NULL), `contact_number` (TEXT NOT NULL), `safety_score` (DOUBLE PRECISION NOT NULL DEFAULT 100.0), `status` (TEXT NOT NULL DEFAULT 'Active').
   - Gaps: `license_expiry_date` stored as TEXT instead of DATE. No `is_active` soft-delete column. No CHECK constraints on `status` or category.

7. **`trips`**
   - Columns: `id` (BIGINT GENERATED BY DEFAULT AS IDENTITY PK), `source_name` (TEXT REFERENCES destinations), `destination_name` (TEXT REFERENCES destinations), `vehicle_reg` (TEXT REFERENCES vehicles), `driver_license` (TEXT REFERENCES drivers), `cargo_weight` (DOUBLE PRECISION NOT NULL), `planned_distance` (DOUBLE PRECISION NOT NULL), `revenue` (DOUBLE PRECISION NOT NULL), `status` (TEXT NOT NULL DEFAULT 'Draft').
   - Gaps: No partial unique indexes preventing two simultaneous `Dispatched` trips for a single vehicle or driver. No CHECK for `cargo_weight > 0` or `source_name != destination_name`.

8. **`maintenance_logs`**
   - Columns: `id` (BIGINT GENERATED BY DEFAULT AS IDENTITY PK), `vehicle_reg` (TEXT REFERENCES vehicles), `description` (TEXT NOT NULL), `cost` (DOUBLE PRECISION NOT NULL), `start_date` (TEXT NOT NULL), `end_date` (TEXT), `status` (TEXT NOT NULL DEFAULT 'Pending').
   - Gaps: No partial index for open maintenance (`WHERE status = 'Open'`). Dates stored as TEXT. No check `end_date >= start_date`.

9. **`expenses`**
   - Columns: `id` (BIGINT GENERATED BY DEFAULT AS IDENTITY PK), `trip_id` (BIGINT REFERENCES trips), `type` (TEXT NOT NULL), `liters` (DOUBLE PRECISION), `cost` (DOUBLE PRECISION NOT NULL), `date` (TEXT NOT NULL).
   - Gaps: No CHECK on `cost >= 0` or expense enum. Date stored as TEXT.

## 4. Status Field Written in Generic Update Bodies (D-04)
- **`PUT /api/v1/fleet/vehicles/{reg}`**: Takes raw `vehicle` struct including `status` and issues `UPDATE vehicles SET ... status=$6`. An operator could illegally move a vehicle directly from `On Trip` or `In Shop` to `Retired` or `Available`.
- **`PUT /api/v1/fleet/drivers/{license}`**: Takes raw `driver` struct including `status` and issues `UPDATE drivers SET ... status=$6`. Allowed bypassing safety review to flip `Suspended` to `Active`.
- **Fix in Phase 2**:
  - Remove `status` from generic `PATCH` requests; reject incoming `status` with 422.
  - Implement dedicated state machine transition actions:
    - `POST /vehicles/{reg}/retire`
    - `POST /drivers/{license}/suspend`, `/reinstate`, `/set-off-duty`, `/set-available`

## 5. Hard Deletes & FK Failures (D-06)
- Current `DELETE /api/v1/fleet/vehicles/{reg}` runs `DELETE FROM vehicles WHERE registration_number = $1`.
- If a trip references this vehicle, PostgreSQL throws constraint violation `23503` (foreign_key_violation).
- Current response is `409 FOREIGN_KEY_VIOLATION` with unhelpful message, preventing legitimate archiving of retired vehicles.
- **Fix in Phase 2**:
  - Soft-delete vehicle/driver (`is_active = false`) if any trip history exists.
  - Reject `409 VEHICLE_IN_USE` / `DRIVER_IN_USE` if active trip (`status = 'Dispatched'`) or open maintenance log exists.
  - Only hard-delete records with zero historical relations.

---

## 6. List Endpoints: Ordering and Limits (P-05)
- Currently, `/vehicles`, `/drivers`, `/destinations`, `/trips` fetch all rows in unbounded queries (`ORDER BY registration_number`, `ORDER BY name`, `ORDER BY id`).
- As data grows, this introduces unindexed full table scans and high p95 response latencies.
- **Fix in Phase 2**:
  - Implement keyset / cursor-based pagination with `cursor` and `limit` (default 25, clamped to 100).
  - Add search `q` and attribute filters (`type`, `status`, `include_inactive`, `license_expiring_within_days`).
  - Standardize response shape: `{"items": [...], "next_cursor": string | null}`.

## 7. Discrepancies Between Go Code Assumptions and DB Enforcement (D-05)
1. **Double Booking**: Code checked vehicle status in memory before dispatch, but concurrent requests could dispatch the same vehicle or driver twice.
   - *Fix*: Partial unique index `trips(vehicle_reg) WHERE status = 'Dispatched'` and `trips(driver_license) WHERE status = 'Dispatched'`.
2. **Negative Values**: Go code accepted negative acquisition cost, negative odometer, and 0 cargo weight.
   - *Fix*: DB check constraints `acquisition_cost >= 0`, `odometer_km >= 0`, `max_load_kg > 0`, `cargo_weight_kg > 0`.
3. **Invalid Enum Strings**: DB accepted arbitrary strings like `"Banana"` for vehicle type, status, or role.
   - *Fix*: DB check constraints validating all enums.
4. **Maintenance Inconsistencies**: Multiple concurrent open maintenance logs could exist for the same vehicle.
   - *Fix*: Partial unique index `maintenance_logs(vehicle_reg) WHERE status = 'Open'`.

---

## 8. Frontend Calls That Will Break with Phase 2 Changes
1. **Generic Status Updates**: Frontend modals sending `{ status: "Retired" }` in `PUT /api/v1/fleet/vehicles/{reg}` must be transitioned to call `POST /api/v1/vehicles/{reg}/retire`.
2. **Pagination Response**: Frontend components expecting raw array `[]` will need to read `response.items` and use `response.next_cursor` for paginated browsing.
3. **HTTP Method**: Transition `PUT` routes to `PATCH` for partial edits.
